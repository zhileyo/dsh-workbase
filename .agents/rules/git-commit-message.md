# Git Commit Message 规范

## 提交格式

```text
<type>：<subject>

1.原因分析：<原因，无则填「无」>
2.修改方法：
1）<具体修改点>
2）<具体修改点>
```

- type 后接全角冒号「：」，不空格，直接接 subject
- subject 一句话概括本次提交，简短且看得懂
- body 固定为「原因分析 + 修改方法」两项，子项用 1）2）3）编号
- type 根据本次 diff 内容自动推断；混合变更按主体内容归类，无法归类时用「其他提交」

## type 说明

| type | 说明 | 本仓库典型场景 |
| ---- | ---- | ---- |
| 新增文件 | 新增笔记或资源文件 | 新建笔记、目录、模板（400_模板中心）、附件（500_附件管理，含 LFS 文件） |
| 文档修改 | 只修改了文件内容 | 笔记正文、README、index.md、log.md 等更新 |
| 样式修改 | 不影响内容的修改 | 格式化、排版调整、frontmatter 规范化 |
| 问题修复 | 修复错误 | 失效内链、链接指向错误、frontmatter 字段填错 |
| 编译代码 | 工具与配置变更 | .obsidian、.trae、脚本（300_Scripts）、.gitattributes / LFS 配置 |
| 其他提交 | 以上之外的提交 | 重命名/移动文件（内容不变）等 |


## subject 规则

- 【问题修复】：简要描述问题现象与影响
- 批量导入、结构性大改等庞大变更应拆分为小的功能点分别提交，便于审核与回溯

## body 规则

- 表达清晰本次提交涉及的原因和具体修改方法
- 【问题修复】必须填写原因分析，其他类型可填「无」
- 修改点多时，用序号 1）2）3）列出各项

## 示例

```plain
新增文件：0X0F_知识沙盒 新增《Docker》概念笔记

1.原因分析：无
2.修改方法：
1）新建笔记并填写 frontmatter 与标签
2）更新 index.md 索引
```

```plain
文档修改：更新 README 目录结构说明

1.原因分析：仓库目录调整后 README 未同步
2.修改方法：
1）同步最新目录树
```

```plain
样式修改：统一笔记 frontmatter 格式

1.原因分析：无
2.修改方法：
1）规范 tags 字段缩进
2）补齐缺失的 updated 字段
```

```plain
Bug 修复：修复 A136_Git 笔记中的失效内链

1.原因分析：目标笔记重命名后原内链未同步，导致跳转失效
2.修改方法：
1）将失效内链更新为重命名后的笔记路径
```
